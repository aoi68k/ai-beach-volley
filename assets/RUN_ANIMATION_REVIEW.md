# 走りモーションの復元と原因調査

## 復元した状態

ゲームと `character-preview.html` は `characters/*-v3.png` の2行目を6コマ・12fpsで再生する状態へ復元した。待機・アタック・ジャンプの各6コマ、トス／レシーブの既存画像は維持。4人のv3 PNGは、変更前に生成された原本とSHA-256が全て一致する。v4のPNGとパーツ・rigは調査用に残すが、ゲームとプレビューでは使用しない。

これは品質劣化の取り消しであり、v3の脚の連続性を解決したことを意味しない。

## 直近のv4が崩れた原因

1. **補間から別方式への変更**。既存の全身絵を維持して足りない姿勢を描く依頼に対し、別に生成した頭胴体・腕・脚のパーツを組み立てる方式へ変えてしまった。その結果、顔・体形・筋肉の描写・シルエットが元の走りと揃わなくなった。
2. **関節の位置だけを合わせ、体の面をつなげていない**。`characters/run-rig.js` の `bone()` は、パーツを矩形として回転・伸縮して重ねる。曲げた膝・肘の輪郭や筋肉、関節を覆う描画がなく、各パーツの黒い輪郭と丸い端が残る。画像でも肩・肘・膝が分離した人形のように見える。
3. **同じパーツを大きく伸縮**。12姿勢の座標を計算すると、大腿の描画軸は31.8〜55.7px、下腿は20.9〜52.6px、手前の上腕は32.2〜58.4px。投影による見かけの長さの変化自体はあり得るが、この実装は奥行きに合わせて描き直さず、同じ画像をその長さへ伸縮している。太さや筋肉の形との整合が失われる。
4. **元絵と独立した寸法・陰影**。胴体を固定倍率0.52、腕・脚を別々の固定幅で描き、4人にほぼ共通の関節座標を使用。大腿の上39%を機械的に切り、奥側の脚と腕だけを明度0.78へ落としている。衣服との接続、元のハイライト、体全体のバランスが揃わない。
5. **全身の走りを再現していない**。胴体は上下するだけで姿勢が固定され、足部は常に水平。足首の返し、蹴り出し、骨盤・肩の回旋に合わせた絵の変形がない。脚の座標を並べても、元絵の躍動感を保つことにはならなかった。

## 元の6コマの問題

ゲームの切り出しは2行目の左から右、256px単位で正常。コードが左右をランダムに交換しているのではない。左右チームの反転も各チームで一定。

問題は絵の中の動作の対応。特に2→3、3→4、5→6のつながりで、支持している脚、前へ振り出す脚、胴体の向きが連続する一周期として揃っていない。前面寄りと背面寄りの胴体が切り替わり、同じ脚を股関節から追うのが難しい。元の生成プロンプトでは左右交互の6段階を指定していたが、出力がその指定を守っているかを十分に検証できていなかった。

再生速度やコマ数を変えるだけでは解決しない。増やした候補でも対応が崩れた際、そこで画像の成立を見直すべきだった。

## 検証と報告の問題

v4のテストが確認したのは、設定した座標が一定範囲内を動くこと、接地用座標の高さ、セルの切り出しなど。画像の解剖学的整合、関節の接続、元絵と同じ体形・画風か、描き出したPNGが自然に見えるかを判定するものではなかった。特に座標のテストは、入力したrig定義を検証するもので、完成画像の品質の証明ではない。

目視でも分離した関節や体形の変化が見えていたのに採用し、「連続性を確認した」「修正完了」と報告した判断が誤りだった。

## 次に修正する場合の条件

- まず1人の既存6コマについて、同じ脚を股関節・膝・足首で追い、支持脚と遊脚の対応、使用できる原画と不足する姿勢を確定する。
- 元絵の顔・頭身・胴体・輪郭・陰影を基準として固定し、必要な中間姿勢を全身絵として描く。今回のパーツ伸縮方式は採用しない。
- 接地→荷重→通過→蹴り出し→遊脚回収を、通常速度・低速・コマ送りで確認する。最後→最初も同様に確認する。
- 元絵と並べて画質を比較し、1人の周期が成立してから他3人へ展開する。

今回は復元と調査のみを実施し、新たな画像生成は行っていない。

## 復元の確認

`node --check game.js`、`node tests/animation.test.cjs` 成功。4人×6セルがv3の元の走り行を参照すること、ゲーム／プレビューにv4への参照がないこと、待機・アタック・ジャンプ・一時停止・画像ロード失敗時の代替描画・30秒相当のCOM動作を確認した。これらは実装の確認であり、未解決のv3の動きの自然さを保証するものではない。
